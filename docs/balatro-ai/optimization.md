# 上下文与执行速度优化

目标是让同一聊天模型在新的原生随机局中更方便地复用自己读过的经验，减少重复上下文、读取与短动作等待。实际胜率和整局时间需要新版实机记录；这里的源码、合成检查和开发STDIO不代替实机对局。

## 改动

| 改动 | 用法与作用 |
| --- | --- |
| 经验发现 | 已知主题批读strategy；新主题用index发现后读strategy，修订才读content/full审计视图。索引不能充作经验依据 |
| 短局内计划 | run_plan保存模型自己的目标、最多4个优先事项、最多4个复查条件、最多6个已读经验版本；构筑或约束变化才修订，压缩后读盘恢复 |
| 更小的返回 | MCP笔记默认strategy，只读判断、条件、反例及置信度；观察默认compact，对至少3个同字段对象按列返回，只有算上协议标记仍更小时才采用 |
| 更短的早期等待 | 前两次状态查询间隔不超过50ms，随后三次不超过100ms，再恢复不超过原配置的200ms；原生回调、相关事件及公开后条件仍必须满足 |
| 更少的工具往返 | 提示明确复用COMPLETED的下一观察、直接原生选牌/目标协议；快速游玩开局前经正常设置菜单核验速度4 |

列式观察保留全部字段、null、未知值与数组顺序。字段集合不同的对象不合并，背面牌较小的白名单不会被填充身份字段；石头牌继续遮蔽点数与花色。原始公开契约与观察编号未改变，full视图可恢复原对象数组。交付审计记录模型实际收到的格式。

计划位于runs/live/run-plans/，开发检查位于隔离的runs/checks/stdio-development/run-plans/。正文最多2000 UTF-8字节，本局最多50次修订，原子替换单个JSON文件并保留该局所有修订。active.json记录已确认start_run/continue_run的公开作用域，并原子保存最近观察编号、档位和已知公开轮次基线；新局、离开对局、公开档位/会话变化或轮次回退使旧计划失效，旧局文件保留。服务重启后只在相同公开决策点仍未改变时恢复；无法确认连续性或旧版记录缺少基线时停止复用，保留历史。历史动作/重复查询的旧快照不更新连续性或当前观察。合法JSON中的错误类型同样按计划损坏报告，不阻断MCP启动。正常显示牌组/注级不等于进入开局设置；原生优惠券降低Ante也不算新局。模型位置和即时资源仍以最新观察为准。

run_plan写入须绑定最近实际交付的当前可操作观察、匹配预期修订、没有未决动作/检查点故障；引用须本MCP进程成功完整读过相应经验版本，strategy也满足读取要求。索引和写入收据不计作完整读取。计划是临时模型记忆，不能作为授权或替代真实游戏事实；计划存储故障单独报告，不把已确认的原生动作改成失败或胜利。计划交付日志失败后按同write_id查询或read核对，write_state=UNKNOWN是计划写入不确定，不代表游戏动作失败。

## 2026-10-12：高注清单与重复调用

主攻略8条清单检查可靠剩余计分、常见手、成长和现金流；橙注主题比较当前阵容、关键易腐失效后及公开Boss限制下的能力，未知商品不能作为接替。它们来自有限失败反馈，租用与采购改进仍未经金注实战验证。两个主题的strategy内容JSON由10005降为5780 UTF-8字节，保留事实与来源；并非token或游玩时间测量。

每局仍实际读主攻略，已知相关主题同次批读；同局清楚的修订不反复读取。最新、非历史且ready的COMPLETED观察直接供下一决策，未决、过渡及缺字段仍按恢复规则查询。只有优先级、构筑约束或复查条件实质变化才写短计划，普通余额变化和出牌不自动修订。非历史动作观察附server_time，可将已确认结算反馈作为计时终点；缺时钟才再observe，历史收据不生成当前交付时钟。

`scripts/project.py timings`沿用离线记录，按工具展示结果UTF-8字节及调用等待，分别统计传输等待、原生完成耗时、轮询次数和调用间隔。这些计时分量有重叠，不能相加；间隔还包含用户暂停及其他维护，不代表纯模型时间。宿主错误不冒充MCP交付，未知数值不记为零。后续正常对局才能检验减少调用是否提高整局速度与通关表现。

## 1.3.0：本步公开变化

顶层public_changes将已交付的公开观察分为已变、已知字段未变、未知和暂不可比较。模型先看changed/unknown，再按自己的计划复查条件判断；完整手牌、资源、操作位置始终取最新观察。Reader与Executor共享审计成功后才推进的内存基线；轮询、未交付结果和隐藏状态不参与。重启、缺口、当前UNKNOWN／待定动作重新建立基线；历史收据不回退计划、当前观察和窗口目标。正常换局与历史查询通过交付语境区分，不能仅凭动作状态推断历史。缺失的适用牌面、弱化／强制选牌状态和区域价格保持未知。详见[双语协议](public-changes.md)。

同版保留full／compact当前观察及12项工具，不选择策略、不额外观察游戏，不证明实机速度或胜率。相同变化保留在本机附加记录；[状态窗口](activity.md)在1.3.1精简为关键阶段、短计划／依据及操作结果，正文隐藏逐字段比较，关闭不影响游玩。

## 运行中断后的可靠性与上下文修订

- 本地HTTP调用使用配置的总时限，覆盖连接、锁等待和整个响应体；省略超时参数不会再把HTTPX超时覆盖成无限等待。health、reader_snapshot和原ID的action_status仅在传输异常时最多重试两次，间隔50／100毫秒，共用原总预算；非法响应、协议错误不重试。act_submit始终只发送一次，响应丢失后仍UNKNOWN并保留意图，只能查询原ID。
- 原生ready检查当前已展示牌的facing与sprite_facing是否一致，避免把翻牌中途反馈交给下一决策。稳定背面牌仍可操作且遮蔽身份；不把原生长期保留的flipping标志当作等待条件，不检查牌堆、未来牌或隐藏身份。完成仍须回调、相关事件、阶段路径和公开后条件，不用相同快照或固定等待替代证明。
- 共用MCP说明改为紧凑英文，参数细节仍在各工具说明，完整规则仍在bootstrap。没有删去UNKNOWN、档位、解锁、单局／爬塔、经验或可见性保护。默认继续使用完整无损compact观察；不会仅根据unchanged删掉当前手牌和操作位置。
- 可选客户端证据包装补齐run_plan，并在动作宿主错误或未决响应后保存原ID、阻止误重放与后续动作。仅原ID查询／观察及受服务校验的丢失会话恢复可接续；正常AWAITING_INPUT返回原生提示处理流程。包装不执行策略、不自动提交恢复后的动作。

这些修订只处理本项目可控的等待、返回与恢复边界。客户端自动审批的外部TLS故障不能由本地Mod消除，也不能以修改审批配置或动作风险标记绕开。源码／合成检查、已加载MCP、已安装Mod和实机速度分别核验；新Mod须下次按正常维护流程安装，不能在保留游戏窗口时热替换。

## 验证与后续

合成检查覆盖无损还原、背面/石头牌遮蔽、未知值、实际交付日志、索引分页与最新磁盘修订、计划独立进程读回、重复ID与修订冲突、旧局失效、未决动作保护和存储故障。开发STDIO阻断真实游戏传输，核验12项工具及新的默认视图。

可复核的大小比较使用公开合成观察和已有只读经验基线；它证明返回更小，不证明模型推理或整局时间按同一比例下降。后续在用户授权的对局中登记相同模型/设置、牌组/注级、经验起点与计时口径，保留所有胜负、故障和UNKNOWN，再评估整局用时、调用次数与通关表现。
